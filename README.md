# Dalbaebik Bot — аналитика КВ-клана STALCRAFT

Discord-бот для сбора и просмотра статистики клана во время КВ. Бот связывает Discord-участников с игровыми никами, отслеживает явку в голосовых каналах, считает время активной речи, снимает значения счётчика гранат STALCRAFT, распознаёт табы со скриншотов и собирает общую статистику эффективности.

## Что умеет бот

- отмечает, кто заходил в настроенные голосовые каналы во время явки;
- показывает, кто сейчас находится в войсе;
- отправляет личные сообщения неявившимся игрокам, кроме «Чемпионов»/замен;
- считает время активной речи с начала первого этапа до финала;
- получает из STALCRAFT eAPI счётчик брошенных гранат и вычисляет дельты по этапам;
- сохраняет табы КВ со скриншотов через Gemini OCR: место, убийства, смерти, помощь и счёт;
- строит `/stats` по одному дню, диапазону дат или всей истории;
- хранит данные в SQLite и восстанавливает незавершённую сессию после перезапуска;
- предоставляет локальную веб-панель для просмотра и исправления статистики;
- синхронизирует состав и отряды из Excel после сохранения файла.

## Как устроен сбор данных

### Явка

Явка учитывается по всем голосовым каналам, добавленным через `/voice_add`. Игрок получает отметку ✅, если хотя бы раз оказался в одном из них во время окна явки.

| День | Окно явки | ЛС неявившимся |
|---|---:|---:|
| Четверг–суббота | 19:30–20:05 МСК | 19:50 |
| Воскресенье | 18:30–19:00 МСК | 18:45 |

### Гранаты

Для игроков из отрядов 1–6 и группы «Чемпионы» бот получает накопительный показатель `gre-thr`. Количество гранат за этап — разница между двумя соседними замерами. Если один из замеров отсутствует или накопительный счётчик уменьшился, значение считается неизвестным, а не нулём.

| День | Замеры |
|---|---|
| Четверг–суббота | база 20:05 → I 20:25 → II 20:50 → III 21:15 |
| Воскресенье | база 19:00 → I 19:20 → II 19:40 → III 20:00 → IV 20:15 |

Промежуточный замер выполняется только в коротком окне после назначенного времени. Если бот был выключен, восстановить прошлое значение накопительного счётчика невозможно.

### Время речи

Автоматический скан начинается на базовом замере и заканчивается на финальном. Учитывается именно активная речь, а не просто нахождение в канале. Звук не записывается и не сохраняется.

> Важно: автоматический скан подключается только к одному — самому заполненному на момент старта — настроенному голосовому каналу. Явка видит все настроенные каналы, но минуты речи игроков из других каналов в этот момент не попадут в статистику.

### Табы со скриншотов

Команда `/scan` отправляет изображение в Gemini и сохраняет распознанные значения в SQLite. Дата КВ обязательна. Повторная отправка идентичного таба определяется по содержимому и не создаёт дубль.

```text
/scan date:13.09.2026 map:Хвойник screenshot:<файл>
```

## Статистика и ЭФФ

`/stats` выводит средние показатели игрока:

- **У** — убийства за сохранённый таб;
- **С** — смерти за таб;
- **П** — помощь за таб;
- **СЧЁТ** — очки за таб;
- **ГРЕНЫ** — гранаты за завершённое КВ;
- **ВРЕМЯ** — активная речь за завершённое КВ;
- **N** — количество табов / количество КВ с замером гранат;
- **ЭФФ** — относительная эффективность среди отображаемых игроков.

Формула ЭФФ использует min-max нормализацию каждого показателя в диапазон 0–100:

```text
KD = средние убийства / средние смерти
norm(x) = 50, если min = max
norm(x) = (x - min) / (max - min) × 100, иначе

ЭФФ = 43.75% × norm(KD)
     + 18.75% × norm(П)
     + 25.00% × norm(ГРЕНЫ)
     + 12.50% × norm(СЧЁТ)
```

В исходном коде веса заданы как `0.35 / 0.15 / 0.20 / 0.10` и нормализуются на их сумму `0.80`, поэтому фактические доли приведены выше. Время речи в ЭФФ не входит. Рейтинг рассчитывается только для отрядов 1–6 и только при наличии всех четырёх боевых метрик.

ЭФФ — относительный рейтинг: значение игрока может измениться при выборе другого периода или состава сравниваемых игроков. Это не абсолютный процент полезности.

Примеры:

```text
/stats
/stats date:13.09.2026
/stats date_from:01.09.2026 date_to:13.09.2026
/stats_dates
```

## Установка

Требуется Python 3.11+.

1. Создайте Discord-приложение и бота.
2. Включите intents **Server Members** и **Message Content**.
3. Скопируйте `.env.example` в `.env`.
4. Установите зависимости и запустите бота:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python bot.py
```

5. В Discord выполните `/setup`, настройте канал логов и войсы, затем добавьте access-роли.

Минимальный `.env`:

```env
DISCORD_TOKEN=your_discord_bot_token
STALCRAFT_CLIENT_ID=your_client_id
STALCRAFT_CLIENT_SECRET=your_client_secret
STALCRAFT_REGION=ru
GEMINI_API_KEY=your_gemini_api_key
```

`GEMINI_API_KEY` нужен только для `/scan`. Не добавляйте настоящий `.env`, токены и базу SQLite в Git — они уже исключены через `.gitignore`.

Дополнительные параметры:

```env
# Excel
SHEET_PATH=C:\Users\you\Documents\roster.xlsx
SHEET_AUTO_SYNC=true
SHEET_WATCH_POLL_SECONDS=0.5
SHEET_WATCH_DEBOUNCE_SECONDS=2
SHEET_WATCH_RETRY_SECONDS=3

# Локальная админ-панель
ADMIN_UI=1
ADMIN_PORT=8787

# Логи
APP_DEBUG=false
APP_LOG_LEVEL=

# Детектор речи
VOICE_SCAN_DBFS_THRESHOLD=-55
VOICE_SCAN_ADAPTIVE_THRESHOLD=false
VOICE_SCAN_MARGIN_DB=12
VOICE_SCAN_ATTACK_MS=60
VOICE_SCAN_RELEASE_MS=1000
```

## Excel-состав

Поддерживаются текущая визуальная сетка отрядов и явный формат листа `roster`:

```text
squad | slot | discord_id | game_nick
```

При включённом `SHEET_AUTO_SYNC` бот следит за изменением файла и запускает синхронизацию после стабильного сохранения. Это файловый watcher, а не периодическая полная синхронизация по таймеру. Ручной запуск — `/sheet_sync`.

Транзакционный импорт с предварительной проверкой:

```bash
python tools/roster_io.py import roster.xlsx --guild-id 123
python tools/roster_io.py import roster.xlsx --guild-id 123 --apply --expected-revision HASH
python tools/roster_io.py export-tech tech.xlsx --guild-id 123
```

Подробнее: [docs/EXCEL.md](docs/EXCEL.md).

SQLite — основной источник данных. `players.json` используется только для одноразовой legacy-миграции и не перезаписывается ботом.

Перед ручным сбросом сессии создаётся резервная копия:

```text
scan_stats.sqlite3.session-reset.bak
```

## Локальная админ-панель

Панель запускается вместе с ботом по адресу <http://127.0.0.1:8787> или отдельно:

```bash
python tools/admin_ui.py
```

Она показывает дни КВ, историю игроков, табы, гранаты и войс, а также позволяет исправлять и удалять значения. Изменения сразу видны в `/stats`.

Панель рассчитана только на доверенный локальный компьютер: в ней нет авторизации и CSRF-защиты. Не публикуйте порт наружу и не меняйте bind с `127.0.0.1` на `0.0.0.0` без добавления защиты.

## Проверки

```bash
python -m compileall -q bot.py player_store.py explicit_roster_io.py sheet_watcher.py tools
python -m unittest discover -s tools -p "test_*.py"
python tools/test_player_store.py
```

`/scan_now` выполняет только один выбранный замер текущей активной сессии. Команда принимает только сегодняшнюю дату и не пытается восстановить исторические значения накопительного счётчика.

Некоторые интеграционные проверки импортируют `bot.py`, поэтому зависимости из `requirements.txt` должны быть установлены.

## Известные ограничения

1. Автоматические минуты речи собираются только в одном голосовом канале одновременно.
2. ЭФФ зависит от выбранного периода и участников сравнения; у показателей могут быть разные размеры выборки.
3. Пропущенный исторический замер гранат невозможно восстановить из текущего накопительного значения eAPI.
4. Локальная админ-панель не предназначена для сетевой публикации.
5. `bot.py` и `player_store.py` крупные и сильно связаны; дальнейшее развитие лучше вести через разделение на модули сервисов, команд и репозиториев данных.
