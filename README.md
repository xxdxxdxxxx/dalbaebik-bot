# Dalbaebik Bot — аналитика КВ-клана STALCRAFT

Discord-бот для управления составом и сбора статистики клана. Основной источник данных — SQLite; состав управляется через локальную админ-панель и синхронизируется с Clan Map и двумя постоянными сообщениями Discord.

## Возможности

- 6 отрядов по 5 игроков и отдельная группа «Замены» на 10 мест (на странице «Отряды» это колонка справа на всю высоту);
- игроки с Discord-привязкой и без неё;
- «ЯВКА НА КВ» и «ГРАНАТЫ» обновляются автоматически;
- явка по голосовым каналам и автоматические ЛС неявившимся;
- автоматический подсчёт активной речи;
- замеры гранат через STALCRAFT eAPI;
- распознавание табов через Gemini OCR;
- статистика и ЭФФ в локальной админ-панели;
- шмот игроков (Снайпы, Кувалда, Огнемёт, Био, Тяж, скорость) на странице «Шмот» админ-панели;
- синхронизация состава с Clan Map;
- заявки на бафы из Discord-канала, таблица выдачи и история в админ-панели;
- восстановление незавершённой сессии после перезапуска.

## Команды

- состав: `/add`, `/remove`, `/alias_add`, `!add`, `!remove`;
- КВ: `/map`, `!map`, `/refresh`, `/scan_now`, `/ls_send`;
- табы: `/scan`;
- бафы: `/buffs_channel`, `/buffs_sync`, `/buffs_off`;
- настройка: `/setup`, `/set_log`, `/settings`, `/voice_add`, `/voice_remove`, `/voice_clear`;
- права: `/access_add`, `/access_remove`, `/access_list`;
- служебные: `/say`, `/help`.

Случайные фразы после добавления игрока и текстовые команды сохранены. Статистика, история табов и рейтинг эффективности доступны только в админ-панели.

## Бафы

Игроки пишут в постоянный канал заявки по шаблону: первая строка — ник, дальше «число + название» через запятую или с новой строки:

```
TergosX
100 мин, 3 убийцы
60 топотов
```

1. В Discord: `/buffs_channel #канал` (нужны права администратора). Бот прочитает последние 500 сообщений и дальше следит за каналом сам;
   правка и удаление сообщения сразу меняют таблицу. `/buffs_sync` перечитывает канал заново и убирает заявки удалённых сообщений,
   `/buffs_off` выключает чтение (таблица очищается, история остаётся). Таблица показывает только текущий канал бафов.
2. В админ-панели раздел **«Бафы»** — одна общая таблица: ник, Шизы, Топоты, Убийцы, Хилки, Напалмы, Смоки, Мины и справа кнопка-галочка «выдано».
   В ней все, у кого есть актуальная заявка, независимо от того, в какой день они написали. Внизу «Итого» и «Осталось выдать», сверху поиск по нику.
   Страница обновляется сама, когда приходит новое сообщение.
3. Во время КВ по галочке отмечают, кому выдали. **Галочка сразу сохраняется в историю**: ник, сколько каких бафов, дата. Повторное нажатие снимает отметку.
4. После КВ (в 05:00 МСК) **галочки сбрасываются, а игроки остаются в таблице** — на следующем КВ их можно отметить снова, и в историю запишется новая выдача.
   С таблицы заявка пропадает только когда сообщение удалили в Discord. Кнопка **«История»** показывает, кто сколько бафов получил и в какие дни
   (по игрокам / по дням), сверху — панель «сколько всего выдано» по каждой категории (шизы, топоты, …), внизу «Итого»; ошибочную запись можно убрать кнопкой «✕».

Как читаются сообщения:

- у каждого игрока в таблице его **последнее** сообщение: чтобы изменить заявку, достаточно отредактировать сообщение или написать новое. Новое сообщение после выдачи — уже новая заявка;
- заявка висит **бессрочно, пока сообщение есть в канале**. Удалили сообщение — заявка исчезла из таблицы, а история выдачи остаётся целиком.
  Если сообщение удалили, пока бот был выключен, при запуске бот сверит последние 1000 сообщений канала и уберёт такие заявки (так же делает `/buffs_sync`);
- ник сверяется с базой игроков так же, как в остальной панели (опечатки и алиасы учитываются); неизвестный ник помечен «нет в базе»;
- если ник забыли, берётся ник по привязке Discord-аккаунта (`/add`);
- названия: шизы, топоты, убийцы (есть и «убиц»), хилки (= подорожник = зелень/зеленка), напалмы, смоки (= завеса = дым), мины. Любая форма слова подойдёт, пара опечаток
  тоже прощается («топтов», «убицы», «падорожник»); слова «ящик/ящика» игнорируются («3 ящика напалма» = 3 напалма).
  Строка с неизвестным словом («3 биозаплатки») не мешает остальным — она только помечается ⚠. После обновления бота `/buffs_sync` (или перезапуск)
  заново разбирает уже сохранённые сообщения, галочки при этом не сбрасываются. Ник и бафы можно написать в одну строку: `Nick 100 топотов, 3 убийцы`.
  Новые названия добавляются в `BUFF_STEMS` в `tools/buffs.py`;
- то, что не разобралось, не пропадает: строка с ⚠ в таблице или раздел «Не распознано» под ней.

## Шмот игроков

Страница **«Шмот»** в админ-панели: игроки из отрядов, внутри отряда — в том же порядке мест, что на странице «Отряды» (не по алфавиту), справа от ника слоты **Снайпы · Кувалда · Био · Тяж · Огнемёт · Скорость**.

- клик по слоту открывает выбор: предмет или «Пусто», внизу — заточка `+0…+15` (по умолчанию +15, последнее введённое значение запоминается до перезагрузки страницы).
  Заточку можно поменять и у уже выбранного предмета: откройте слот, впишите число, Enter;
- у слота три состояния: **не указано** — тёмный пунктирный слот с «+» (ещё не заполняли); **«Пусто»** — у игрока этого предмета нет: ровный пустой слот без «+» и без штриховки со сплошной рамкой, подсказка «нет» (сохраняется в базе, `NONE_KEY = "none"` в `tools/gear.py`); выбранный предмет. Кнопка **«↺ Сбросить»** в окне выбора возвращает слот в «не указано». У «Пусто» заточки нет;
- фон слота под иконкой — переменные `--g-bg` (`#0f1419`) / `--g-bg-hi` (при наведении, `#18202a`) в `.g-slot` в `tools/gear.py`; при желании можно сделать светлее — тогда лучше видны тёмные иконки (`#222b36` / `#2d3844` пробовали, не подошло);
- рамка слота — по редкости: легендарный `#CC9933` (Гаусс, Кувалда, Штурма, Зивка), исключительный `#933` (Огнемёт, SBA ТАНК, Вождь и три новых снайпера в категории «Снайпы»: `sniper1` — **EBR**, `sniper2` — **pZB**, `sniper3` — **СВД-м**; названия меняются в `ITEMS` в `tools/gear.py`, ключи `sniper1…3` трогать нельзя — они записаны в базе). `+N` рисуется в правом нижнем углу, `+0` не подписывается. **Исключение — «Снайпы»**: там вместо «+N» внизу иконки по центру написано название (Гаусс, EBR, pZB, СВД-м) — белым, без обводки; заточка при этом сохраняется и видна в подсказке при наведении (`EBR +15`) и в окне выбора. Включается флагом `show_name=True` у колонки в `COLUMNS`, стиль — `.g-nm` в `tools/gear.py`;
- **Скорость** — двузначное число `10–99` (`39`, `40`, `25`…) или прочерк: пусто, `-` или `—`. В поле проходят только цифры, одна цифра, три цифры и текст отклоняются с сообщением. Скорость привязана к игроку так же, как предметы. Записи из старой версии (например, `33 32 45`) не стираются, а подсвечиваются красной рамкой, пока их не заменят;
- сохраняется сразу по клику / Enter, данные лежат в таблице `player_gear` и привязаны к игроку, а не к месту в отряде: при свапе ячеек на странице «Отряды» (в том числе между отрядом и Чемпионами) шмот едет вместе с игроком; убрали из отряда (на доске или `/remove`) и добавили снова по тому же нику — шмот на месте; при слиянии дублей ника шмот переезжает к оставшемуся игроку;
- таблица на всю ширину панели, как «Игроки»: ник слева, иконки и скорость примерно по центру, справа свободное место; шапка (Ник · Снайпы · Кувалда …) залипает при прокрутке, как в «Бафах»; скорость стоит по центру под заголовком (правится в `CSS` в `tools/gear.py`: ширина колонки иконок — `.gt td.g-c`, скорости — `.gt td.g-w`);
- предметы и категории — словари `ITEMS` и `COLUMNS` в `tools/gear.py`, иконки — `tools/gear_icons/<ключ>.webp` (чтобы поменять иконку, достаточно заменить файл с тем же именем).

## Архив дней КВ

На странице дня в админ-панели есть кнопка **«Удалить день (в архив)»**: день пропадает из списка дней, из итогов игроков (дни, гранаты) и из EFF.
Данные не стираются, а помечаются в таблице `archived_days`, поэтому бот не восстановит день заново при перезапуске.
Архивные дни лежат в разделе «Архив» (ссылка на странице «Обзор»), оттуда день возвращается кнопкой «Вернуть».
Новые табы за архивный день сохраняются, но остаются скрытыми, пока день не вернуть.

## Статистика дня — только игроки с таба

Отчёт гранат/войса бот пишет на весь состав, а таб привязывается к дню уже после КВ. Поэтому, как только к дню привязан хотя бы один таб,
**в статистику этого дня идут только игроки, найденные на табах дня**. Не игравшие (нет ни на одном табе) не учитываются:

- на странице дня `/day/<дата>` их нет в таблице и в итогах (Игроков / Гранат / Войс); внизу свёрнутый список **«Не в табе (N)»** — это и есть архив: ник, гранаты, войс;
- **«Игроков»** в дне — сколько игроков на табе. В него входят и те, кого на табе видно, но в отчёте гранат/войса нет (строка «только таб»): таб показал 30 человек — в дне и в списке дней будет 30. Если табов у дня нет (или ни один ник не опознан), «Игроков» — сколько просканировано в отчёте;
- в «Обзоре» и «Архиве» (игроки, гранаты, войс дня), на странице «Игроки» (дни и грены), на странице игрока (история по дням и снапшоты) и в `collect_kv_daily_stats` их день тоже не считается;
- в дне без таба всё как раньше — считается весь отчёт;
- если ни один ник таба не опознан, фильтр не включается (пустой таб не прячет весь состав).

Данные **не удаляются**: строки `kv_daily_players` лежат как были, фильтр работает при чтении (`player_store.tab_roster_by_day`, `played_filter`).
Поэтому всё обратимо: удалили или поправили таб, добавили игроку алиас (`/alias_add`) — и он сразу возвращается в день. Табы, ники которых не нашлись в базе,
и неполный набор табов (загружено меньше этапов, чем в отчёте) помечаются предупреждением в списке «Не в табе».
Страница «Заход войс» не меняется: она про время захода в войс, а не про статистику.

### Перепривязка ников табов

К игроку строка таба привязывается один раз — при загрузке скриншота, по нику. Если потом ник сменил владельца (например, старый игрок
пересел на другой ник, а прежним ником стал играть новый человек), уже сохранённые табы остаются у прежнего игрока: у него двойная
статистика за день, а у нового игрока пусто. На странице дня для этого есть кнопки **«↻ Перепривязать ники табов»** (все табы дня)
и **«↻ ники»** у каждого таба (только он).

1. Открывается **предпросмотр** — ничего не меняется. Группы вида «Пельмешек: Meid → Пельмешек, 3 строки» с галочками.
2. **«Применить выбранное»** меняет только привязку строки к игроку. Цифры табов, отчёты, войс, составы и Дискорд-привязки не трогаются,
   ничего не удаляется и не сливается; другие дни не затрагиваются.
3. Меняются только однозначные совпадения (точный основной ник или алиас). Нечёткие и неопознанные строки остаются как были.
   Если ник записан основным у одного игрока и алиасом у другого, он показан как **конфликт**, галочка снята: включайте, только если
   ник сейчас действительно принадлежит игроку с таким именем.
4. Каждая смена пишется в журнал `scan_relink_log`; внизу страницы предпросмотра **«↩ Вернуть»** откатывает пачку
   (строки, которые с тех пор менялись, пропускаются).

Применять стоит к дням, когда ник уже принадлежал новому игроку: в старых днях тот же ник мог быть другим человеком.

## EFF и период на странице «Игроки»

Сверху на странице «Игроки» выбирается период: последние 1, 2, 3, 5, 7, 14, 30 дней КВ или «Всё время» (`/players?days=N`, `?days=all`).
Дни, Грены и EFF считаются только по выбранным дням (архивные дни не учитываются).

EFF дня считается так: **каждый таб сравнивается отдельно**, потому что у всех игроков одного таба условия одинаковые (карта, соперник). В табе игрок получает место среди остальных игроков клана на этом табе по шкале 0–100 (лучший 100, худший 0, при равных результатах — среднее): по убийствам 30%, KDA 30% и счёту 25%. Боевой EFF за день — среднее по табам игрока. Один рекордсмен больше не прижимает остальных к нулю, а табы разной тяжести не смешиваются. Таб, где распознан один игрок, не считается: сравнивать не с кем.
Гранаты — 15%: место по «гранатам на таб» среди игроков дня, у которых гранаты есть. Войс в EFF не входит.
Если у игрока нет гранат (не отсканировали, нет в отчёте) **или записан 0**, гранаты в его EFF не участвуют: он считается только по табу, веса остальных показателей пересчитываются. Ноль приравнен к «нет данных», потому что раньше сохранение страницы дня превращало неотсканированные гранаты в 0. Если нужно, чтобы реальный ноль снижал EFF, поставь `GRENADES_ZERO_IS_MISSING = False` в `tools/admin_ui.py`.
На странице дня пустое поле гранат («—») означает «не отсканировано»; сохранение страницы больше не превращает его в 0.
Итоговый EFF игрока — среднее по выбранным дням.

## Заход в войс

На странице «Игроки» кнопка **«🎙 Заход войс»** (`/players/voice`) открывает таблицу: игроки из отрядов (1–6 и «Чемпионы») × дни КВ, которых нет в архиве.
В ячейке — время (МСК), когда игрок **впервые** зашёл в войс на КВ в этот день; «—» — не заходил (или день был до появления этой функции).
Время записывает бот, пока КВ-сессия живая (с начала явки до финала): на событие `on_voice_state_update` и при обновлении войсов.
В таблицу `voice_join_times` оно пишется один раз за день и игрока — повторные заходы и рестарт бота его не меняют.
Если бот запустили, когда игрок уже сидел в войсе, записывается момент, когда бот это увидел.
День, убранный в архив, пропадает из таблицы вместе с остальной статистикой и возвращается кнопкой «Вернуть».

## Админ-панель

Панель слушает только `127.0.0.1:8787` (порт наружу не открывается никогда).

**Локально / через SSH-туннель** — как раньше, без пароля: `ssh -L 8787:127.0.0.1:8787 user@host`, затем `http://localhost:8787`.
Пока `ADMIN_PASSWORD` не задан, панель отвечает только на `localhost`; любой запрос через прокси или по чужому имени хоста получает 403.

**Из интернета по паролю** — в `.env` добавьте:

```
ADMIN_PASSWORD=<длинный случайный пароль>
ADMIN_TRUST_PROXY=1
```

и поставьте перед панелью HTTPS-прокси (Caddy / Cloudflare Tunnel / Tailscale Funnel), который проксирует на `127.0.0.1:8787`.
Вход: форма пароля → cookie на 7 дней (`ADMIN_SESSION_DAYS`). Защита: HTTPS обязателен, cookie `HttpOnly; Secure; SameSite=Lax`,
проверка `Origin` на POST, 5 неверных паролей с одного IP → блокировка на 15 минут, смена пароля разлогинивает всех.
Пример для Caddy:

```
panel.example.com {
    reverse_proxy 127.0.0.1:8787
}
```
